DOG MANAGER — CONFIGURAZIONE (database, AI, servizi esterni)
=============================================================

NESSUNA chiave va scritta nel codice, nel repository o nel frontend.
Il file .env.example elenca le variabili: copiatelo in ".env.local" (che NON viene mai pubblicato).

A) DATABASE E ACCOUNT — SUPABASE (necessario solo per l'uso in famiglia)
-----------------------------------------------------------------------
1. Creare un progetto su https://supabase.com (piano gratuito sufficiente).
2. Aprire "SQL Editor" e incollare tutto il file  supabase/migrations/0001_init.sql, poi "Run".
   (Oppure con la CLI Supabase:  supabase link  e  supabase db push.)
3. Authentication -> URL Configuration: "Site URL" = indirizzo dell'app pubblicata.
   Authentication -> Providers -> Email: attivo. Consigliato: conferma email attiva.
4. Project Settings -> API: copiare "Project URL" e "anon public key" in .env.local:
      VITE_SUPABASE_URL=...
      VITE_SUPABASE_ANON_KEY=...
   (L'anon key è pensata per essere pubblica: la protezione è data dalle regole RLS del database.
    NON usate MAI la "service_role key" nel frontend.)
5. Con la CLI Supabase distribuire le funzioni:
      supabase functions deploy ai-chat
      supabase functions deploy invite
      supabase secrets set GEMINI_API_KEY=<la vostra chiave> SITE_URL=<indirizzo app>
6. Primo accesso: registratevi nell'app, create la famiglia (voi diventate amministratore),
   poi invitate i familiari da Impostazioni -> Famiglia.

B) INTELLIGENZA ARTIFICIALE — GOOGLE GEMINI
-------------------------------------------
- Chiave: https://aistudio.google.com/apikey
- In cloud: è un segreto di Supabase (comando al punto A5). Il frontend non la vede mai.
- In locale (sul PC): impostate la variabile d'ambiente GEMINI_API_KEY prima di avviare l'app.
  PowerShell (solo per questa sessione):   $env:GEMINI_API_KEY = "la-vostra-chiave"
  Oppure impostatela nelle variabili d'ambiente utente di Windows.
- Modello: GEMINI_MODEL (predefinito gemini-3.1-flash-lite). Alcuni modelli non sono disponibili
  per tutte le chiavi: se compare "modello non disponibile", cambiate GEMINI_MODEL.
- Se la chiave manca o il limite gratuito è finito, l'app mostra "AI non disponibile" o
  "Limite di utilizzo raggiunto". Non simula mai risposte. Tutto il resto continua a funzionare.
- La pagina Impostazioni -> Intelligenza artificiale mostra lo stato (attiva / non disponibile).

C) PUBBLICAZIONE — CLOUDFLARE PAGES
-----------------------------------
1. Caricare il progetto su un repository GitHub (privato). Il file .gitignore esclude già .env e node_modules.
2. Cloudflare -> Workers & Pages -> Create -> Pages -> collegare il repository.
   Build command:  npm run build      Output directory:  dist
3. Environment variables (Settings): VITE_SUPABASE_URL e VITE_SUPABASE_ANON_KEY.
4. Dopo il deploy, impostare lo stesso indirizzo in Supabase (Site URL) e come SITE_URL.
I file public/_redirects e public/_headers sono già pronti.
IMPORTANTE: su Cloudflare Pages non esiste il server AI locale: l'AI funziona solo tramite la
funzione Supabase "ai-chat" (modalità cloud).

D) NOTIFICHE
------------
Promemoria nell'app e notifiche del dispositivo funzionano mentre l'app è aperta (attivarle in
Impostazioni). Le notifiche "push" ad app completamente chiusa non sono ancora implementate.
